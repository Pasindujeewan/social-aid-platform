# Non-Functional Requirements

## 1. Introduction

Non-functional requirements describe how the Social Aid Platform should perform.

## 2. Performance

- The system should respond to normal user requests within a reasonable time.
- The system should support multiple users at the same time.

## 3. Security

- User passwords shall be securely stored.
- Users shall only be able to access functions permitted for their role.
- Sensitive user information shall be protected.

## 4. Usability

- The system should have a simple and easy-to-understand interface.
- Users should be able to complete common tasks with minimal steps.
- The platform should work on both desktop and mobile devices.

## 5. Reliability

- The system should handle errors without crashing.
- User data should not be lost during normal system operation.

## 6. Availability

- The platform should be available whenever users need to access the service, except during planned maintenance.

## 7. Maintainability

- The application should use a clear and organized code structure.
- The system should be easy to maintain and update.
